# 일일호프 모바일 주문 웹앱

손님은 테이블 QR로 메뉴를 고르고 계좌이체 안내를 받습니다. 별도 스텝 사이트 `admin.html`을 함께 배포하도록 만들었습니다. Supabase 연결을 완료하면 손님 주문이 데이터베이스에 저장되고, 등록된 스텝들이 로그인해 같은 주문·입금·조리·서빙 현황을 실시간으로 함께 볼 수 있습니다. 현재 폴더에는 행사 프로젝트의 Supabase URL/공개 키가 없어서, 연결 전까지 주문은 각 손님 브라우저에만 저장됩니다.

행사 기본 이름은 **스시X가리아 일일호프**이며, 첫 화면은 할로윈 테마로 꾸몄습니다. 메뉴표의 카테고리와 가격을 앱 및 서버 검증에 함께 반영했습니다. 할로윈 정식 또는 special 세트를 장바구니에 담으면 전용 에이드 맛 선택 칸이 나타납니다. 청포도·블루레몬·자몽 중 선택한 맛은 주문 정보와 운영자 화면에 별도 저장됩니다. 기본 계좌 안내는 **토스뱅크 1002-7989-3300**입니다. 예금주는 전달받지 않아 `확인 필요`로 표시합니다. 결제 안내에는 계좌번호 복사 버튼과 강조된 `입금 후 꼭! 스텝을 불러주세요` 문구가 표시됩니다. 계좌가 바뀌거나 예금주를 확인하면 `/admin.html` 설정에서 수정하세요.

새 메뉴표의 가격과 네 가지 세트 구성을 반영했습니다. **할로윈 ! special ! 세트**는 25,000원이며, 손님 화면에는 `60세트 한정` 안내만 표시하고 판매 수량은 보여 주지 않습니다. 운영자 주문 현황에서만 판매 수량을 확인할 수 있습니다. Supabase 연결 시 데이터베이스가 주문 수량을 원자적으로 관리해 전체 60세트까지만 주문을 허용합니다. DB 미연결 모드에서는 한정 수량과 판매 집계가 해당 브라우저의 로컬 주문만 기준으로 하므로 여러 휴대전화 전체 수량을 보장하거나 집계하지 못합니다.

## DB 미연결 모드

- 앱은 Supabase 설정이 비어 있어도 주문 제출과 계좌이체 안내를 진행합니다.
- 미연결 상태의 주문은 주문한 브라우저의 로컬 저장소에만 남습니다. 운영자 화면에서는 같은 브라우저에서 생성된 주문을 볼 수 있고 입금·조리 상태도 바꿀 수 있지만, 손님 휴대전화에서 생성된 주문은 운영자 기기나 다른 기기로 전달되지 않습니다. 브라우저 데이터를 삭제하면 로컬 주문이 사라질 수 있습니다.
- DB 미연결 상태에서는 운영자 화면을 열 수 없습니다. 공용 주문 내역을 모든 기기에서 함께 보려면 Supabase 연결과 운영자 계정 권한 등록이 필요합니다.
- `admin.html`은 로그인한 스텝용 공용 주문 현황 사이트입니다. 연결 후 사이트 주소 뒤에 `/admin.html`을 붙여 운영진에게 공유합니다. 여러 테이블/휴대전화 주문을 한 곳에서 관리하려면 Supabase 연결이 필요합니다. 연결 후 `/admin.html`에서 행사명과 계좌 정보도 설정할 수 있습니다.

## 구성

- `index.html`, `styles.css`, `app.js`: 모바일 주문과 관리자 웹 화면
- `config.js`: Supabase 프로젝트 주소와 공개 키 설정
- `supabase.sql`: 테이블, 권한 정책(RLS), 주문 저장 함수

## 처음 설정하기

1. [Supabase](https://supabase.com/)에서 새 프로젝트를 만듭니다. 데이터베이스 리전은 실제 행사 운영 지역에 가까운 곳을 선택하세요.
2. 프로젝트 대시보드의 **SQL Editor**에서 `supabase.sql` 전체를 실행합니다. 테이블 생성, 가격 서버 검증, 중복 재시도 방지, 손님 접근 차단, 관리자 권한 정책이 설정됩니다.
3. **Project Settings → API**에서 Project URL과 publishable key(기존 프로젝트의 anon public key도 가능)를 확인해 `config.js`에 입력합니다.

   ```js
   window.APP_CONFIG = {
     supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
     supabaseAnonKey: 'YOUR_PUBLISHABLE_KEY'
   };
   ```

   공개 키는 브라우저에 들어가는 값입니다. `service_role` 또는 secret 키는 절대 넣지 마세요.

4. **Authentication → Users**에서 공용 운영자 계정을 한 번 만듭니다. 이메일 칸에는 `staff@crvgopaobmeifxubevyd.supabase.co`를 입력하고 운영진만 아는 비밀번호를 설정한 뒤 자동 확인(Confirm user)을 켜세요. 사이트 로그인 화면에는 이메일이 표시되지 않고 비밀번호만 받습니다. 만든 사용자의 UUID를 확인하고 SQL Editor에서 아래 문장을 실행해 관리자 권한을 부여합니다.

   ```sql
   insert into public.admin_users(user_id)
   values ('AUTH_USER_UUID');
   ```

   이 공용 계정 하나를 모든 스텝 기기에서 사용합니다. `admin_users`에 등록되지 않은 계정은 주문 목록이나 설정을 볼 수 없습니다.
5. 앱을 HTTPS 정적 웹 호스팅에 배포합니다. 예: Netlify, Cloudflare Pages, GitHub Pages. `index.html`을 직접 열면 브라우저의 보안 정책 때문에 데이터베이스 요청이 제한될 수 있으니 웹 호스팅을 사용하세요.
6. 배포된 `/admin.html` 주소를 스텝들에게 공유합니다. 실시간 주문 업데이트를 위해 `supabase.sql`은 orders/order_items 테이블을 `supabase_realtime` publication에 추가합니다. 할로윈 특가 판매 수량은 이 운영자 화면에서만 표시됩니다. 최신 SQL을 적용하면 손님용 공개 함수는 남은 수량의 참/거짓만 반환하고, 재고 상세 조회는 관리자 계정으로 제한됩니다.
7. 손님용 `index.html` 주소를 QR 코드로 만들어 테이블에 붙입니다. 모든 테이블에 같은 URL을 쓸 수 있고, 손님이 주문할 때 테이블 번호를 입력합니다.
8. `/admin.html`에서 운영진 계정으로 로그인한 뒤 **행사명·입금 계좌 설정**에서 행사 이름, 은행, 계좌번호, 예금주를 입력하고 저장합니다. 계좌번호와 예금주를 모두 입력하기 전에는 손님에게 `계좌정보 준비 중`만 표시됩니다.

## 행사 중 운영

- 관리자 화면의 **주문 처리 현황**에서 테이블, 주문 시간, 메뉴별 수량을 보고 제공된 메뉴를 체크합니다. 모든 메뉴를 체크해도 기록은 목록에 남으며, 완료 카드로 구분됩니다.
- 관리자 화면의 **주문 관리**에서 주문번호, 테이블, 메뉴, 수량, 요청사항을 확인합니다.
- 입금 내역을 실제 은행 앱에서 확인한 뒤 해당 주문을 `입금 확인`으로 직접 바꿉니다. 이 앱은 은행과 연동되지 않아 입금 여부를 자동으로 확정하지 않습니다.
- **조리 상태**를 신규 주문 → 조리 중 → 조리 완료 → 서빙 완료로 변경합니다.
- **주문 집계**에서 메뉴별 수량과 전체 주문 금액 합계를 확인합니다. 필요하면 새로고침으로 최신 주문을 불러옵니다.
- 손님이 같은 주문 요청을 네트워크 재시도로 반복해도 주문 토큰으로 중복 생성되지 않습니다. 총액은 클라이언트 값에 의존하지 않고 데이터베이스가 등록된 메뉴 가격으로 계산합니다.

## 데이터와 보안

- Supabase Postgres를 사용하면 새로고침, 다른 기기 접속, 동시 주문에도 데이터가 유지됩니다. 제공 체크는 `order_items.served`에 저장됩니다. `supabase.sql`을 기존 프로젝트에 다시 실행하면 제공 상태 필드, 관리자 수정 정책, 실시간 publication 구독이 추가됩니다.
- 관리자 화면은 주문과 메뉴 제공 상태 변경을 실시간 구독하므로 접속한 스텝들의 처리 현황이 함께 갱신됩니다.
- Supabase의 Row Level Security 정책이 주문 목록·상태 변경·계좌 설정을 관리자에게만 허용합니다. 비로그인 손님은 `place_order` 함수로 주문을 저장할 수 있지만 전체 주문 테이블은 읽을 수 없습니다.
- 주문 확인 영수증 복구 토큰은 브라우저 로컬 저장소에 보관하고, 데이터베이스에는 토큰의 해시만 저장합니다. 브라우저 저장소를 삭제하면 해당 기기에서 과거 영수증을 다시 열 수는 없지만 운영자 주문 내역은 계속 보관됩니다.
- Supabase 무료/유료 한도, 백업 보존, 인증 이메일 설정은 Supabase 계정 요금제와 프로젝트 설정을 따릅니다. 행사가 끝나면 프로젝트를 보관하거나 삭제하세요.

## 가격 변경

화면 메뉴 가격은 `app.js`, 서버 가격 검증은 `supabase.sql`의 `place_order` 함수에 각각 정의되어 있습니다. 메뉴나 가격을 바꿀 때는 두 곳을 함께 수정한 뒤 웹앱을 다시 배포하세요. 서버 함수의 가격이 최종 결제 금액의 기준입니다.
